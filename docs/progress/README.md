# Implementation progress

ADR-style entries — one per unit of work. Each records **what was done** and
**what's next**, so the history of the build is legible without reading every
commit. Entries are named by kebab-slug (`<slug>.md`) and are **not numbered** —
sequential numbering was dropped because parallel branches kept colliding on the
next number.

Because the filename no longer carries order, **the [Index](#index) below is the
only record of build order** — entries are listed oldest-first and a new entry is
**appended to the bottom**, never inserted mid-list. Keep that order; it's the
chronological spine the old `NNNN-` prefix used to provide.

Every change ships with a progress entry or an update to one (see
[`../../CLAUDE.md`](../../CLAUDE.md) # Documentation discipline).

## Up next

The implementation slice queue, ordered. Each item links back to the progress entry whose "what's next" it satisfies. Pull the top item; when it lands, write the next entry and re-order. Design topics (not implementation slices) live in [`../specs/NEXT.md`](../specs/NEXT.md).

This is the **maintainer's critical-path** queue. Work carved off for **parallel contributors** lives in [GitHub Issues](https://github.com/malmoos/malmo/issues) (some items there are pulled from these "what's next" follow-ups). The two are kept from overlapping on purpose. See [`../dev/contributing.md`](../dev/contributing.md) for the contributor loop.

1. **Persistent journal.** [container-logs-journald-driver.md](container-logs-journald-driver.md) made container logs reach journald, but neither image creates `/var/log/journal` or sets `Storage=persistent`, so the journal is volatile and app-log scrollback is lost on every reboot — `LOGGING.md` # Per-app logs promises "scrollback up to journald's cap". Ship the journald drop-in from `LOGGING.md` # Tuning (`Storage=persistent`, `SystemMaxUse=1G`, `RuntimeMaxUse=128M`) on both images, sized against the root partition that grows at first boot. Also restores the size-based backpressure # Tuning assumes now that docker's per-unit rate limit is off.
2. **GPU + device capacity enforcement.** `install-permissions-enforcement.md` deferred `gpu` enforcement and device-existence validation (both need a host hardware-introspection endpoint). A 422 from the brain will surface correctly in the UI via the existing `dialogError` path ([install-consent-ui.md](install-consent-ui.md)) once the host endpoint lands. See `NEXT.md` # GPU.

| [host-agent-restart-keeps-brain-socket.md](host-agent-restart-keeps-brain-socket.md) — **Closes #447.** Follows [update-target-read.md](update-target-read.md), whose new assertion found this and worked around it. `host-agent.service` declared `RuntimeDirectory=malmo` alone; systemd deletes that directory on stop and makes a **new inode** on start, while the brain reaches the agent socket through a bind mount of the *directory* that Docker resolves when the container **starts**. | [ssh-per-account-access.md](ssh-per-account-access.md) — **Closes #463.** SSH existed only on paper: specced for the appliance in `AUTH.md`/`BUILD.md`, locked **off** for hosted, and **zero code anywhere**. Now decided, written down, and built from the brain's API to the sshd config. **The mandatory auth factor is the profile's** — a public key on hosted, the malmo password on the appliance — with the other available as a required **second** method (`AuthenticationMethods publickey,password`), never as an alternative, because an account's security is set by its weakest accepted method. The one-password rule was a decision about a **LAN**, not about passwords: it holds where nftables keeps :22 to RFC1918+mesh, and on a public box it would turn a household password into an internet-facing credential **and** a second door to the credential the brain's login throttle guards, which sshd knows nothing about. **:22 is open only while someone has SSH on**, replacing daemon-on-with-an-empty-allowlist — and that works because the box is its own perimeter, **measured**: the cloud repo's Hetzner create sets no `Firewalls` field and that package has no firewall code, so no in-guest `nftables` ruleset was needed (one was deferred on purpose in 2026-06-19). New `POST /v1/ssh/set-access` carries one account's **full** state so a retry converges; `internal/hostagent/sshaccess` renders the drop-in **whole** (global `AllowUsers` + one `Match User` block each), writes keys **before** the config, runs `sshd -t` **before** the reload, and **reloads rather than restarts** so live sessions survive. An empty set writes `DenyUsers *`, since omitting `AllowUsers` means *every* account to sshd; `Match` blocks go last, since a global written after one silently joins it. Brain side: two additive tables, `/api/v1/me/ssh` (My-account, every user), elevation-class with success+failure audits, hosted refusing an enable with no key and refusing to drop the last key while enabled, and keys **re-serialised from the parsed key** so a paste cannot smuggle `command=`/`from=` options. **Gaps:** never run against a real sshd or systemd — the daemon lifecycle *is* the port control and a unit test cannot show a port closing, so the issue's own "Done when" is unmet pending a booted box; no UI; the hosted image still ships no `openssh-server` and the lean lockfile still bans it; nothing polls `/v1/ssh/state`, so drift is not surfaced | done |
